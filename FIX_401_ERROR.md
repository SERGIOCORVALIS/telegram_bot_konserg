# 🔧 Исправление ошибки 401 (Unauthorized)

## Что было исправлено

1. **Добавлена очистка API ключей** - Теперь API ключи OpenRouter очищаются от пробелов и кавычек (как и токен Telegram)
2. **Улучшено логирование** - Добавлена детальная информация о загруженных ключах при старте
3. **Специальная обработка ошибки 401** - Теперь при ошибке 401 выводится подробная диагностическая информация

## Причины ошибки 401

Ошибка 401 (Unauthorized) может возникать по следующим причинам:

### 1. Проблемы с форматированием в Railway
- **Лишние пробелы** до/после значения переменной
- **Кавычки** вокруг значения (Railway иногда добавляет их автоматически)
- **Неправильное копирование** (неполный ключ)

### 2. Неверный API ключ
- Ключ истек или был отозван
- Ключ скопирован не полностью
- Используется ключ от другого сервиса

### 3. Проблемы с токеном Telegram
- Неверный формат токена
- Токен был отозван в @BotFather
- Лишние пробелы или кавычки

## ✅ Что нужно проверить на Railway

### Шаг 1: Проверьте переменные окружения

1. Откройте Railway Dashboard → Ваш сервис → **Variables**
2. Проверьте каждую переменную:

**TELEGRAM_BOT_TOKEN:**
- ✅ Формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`
- ✅ Без пробелов в начале/конце
- ✅ Без кавычек (`"` или `'`)
- ✅ Полный токен скопирован

**OPENROUTER_API_KEY:**
- ✅ Формат: `sk-or-v1-...` (должен начинаться с `sk-or-v1-`)
- ✅ Без пробелов в начале/конце
- ✅ Без кавычек
- ✅ Полный ключ скопирован (обычно ~70 символов)

### Шаг 2: Пересоздайте переменные (если нужно)

Если есть сомнения в правильности переменных:

1. **Удалите** переменную (кнопка корзины)
2. **Создайте заново** с правильным значением
3. Убедитесь, что:
   - Имя переменной написано правильно (регистр важен!)
   - Значение скопировано полностью
   - Нет пробелов/кавычек

### Шаг 3: Проверьте логи после деплоя

После обновления кода и перезапуска сервиса, проверьте логи:

```
✅ Хорошие логи (все работает):
Loaded 5 API keys and 4 models
API Key 1: sk-or-v1-...REDACTED (length: 70)
API Key 2: sk-or-v1-...REDACTED (length: 70)
Telegram token: <telegram-token>...REDACTED (length: 46)
Starting bot polling

❌ Плохие логи (проблема):
API Key 1: sk-or-v1-...REDACTED (length: 72)  ← Длина больше = лишние символы!
❌ 401 Unauthorized - API key authentication failed!
```

### Шаг 4: Проверьте длину ключей

**Правильные длины:**
- Telegram токен: ~46 символов (формат: `число:буквы_и_цифры`)
- OpenRouter ключ: ~70 символов (формат: `sk-or-v1-...`)

Если длина отличается - проверьте, что ключ скопирован полностью.

## 🔍 Диагностика через логи

После обновления кода, в логах Railway вы увидите:

1. **При старте:**
   ```
   Loaded X API keys and Y models
   API Key 1: sk-or-v1-...REDACTED (length: 70)
   Telegram token: <telegram-token>...REDACTED (length: 46)
   ```

2. **При ошибке 401:**
   ```
   ❌ 401 Unauthorized - API key authentication failed!
      Model: google/gemini-2.0-flash-exp:free
      Key preview: sk-or-v1-...REDACTED (length: 70)
      Check: 1) Key is correct 2) No extra spaces/quotes 3) Key is active
   ```

## 🆘 Если все еще не работает

1. **Проверьте формат ключей:**
   - Telegram: `число:буквы_и_цифры`
   - OpenRouter: `sk-or-v1-...` (начинается с этого)

2. **Получите новые ключи:**
   - Telegram: [@BotFather](https://t.me/BotFather) → `/revoke` → `/newbot`
   - OpenRouter: [openrouter.ai/keys](https://openrouter.ai/keys) → создайте новый ключ

3. **Проверьте, что переменные добавлены в правильный сервис:**
   - Убедитесь, что добавляете в сервис, который запускает бота (не в базу данных)

4. **Проверьте тип сервиса:**
   - Settings → Service Type должен быть `Worker` (не Web Service)
